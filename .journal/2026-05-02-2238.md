## Problem: Type Incompatibility After Bump

`bun tsc --noEmit` failed with:

```
TS2322: Type '(config: Config) => Promise<void>' is not assignable to type '(input: Config) => Promise<void>'.
```

**Root Cause**: The `Config` types from `@opencode-ai/plugin` and `@opencode-ai/sdk` diverged at some point between `1.1.27` and `1.14.31`. Their `plugin` property now has different types:

- **SDK `Config`**: `plugin?: Array<string>`
- **Plugin `Config`**: `plugin?: Array<string | [string, PluginOptions]>`

The `Hooks.config` callback uses the plugin's `Config`, but `src/design-lab.ts` was importing `Config` from `@opencode-ai/sdk` and explicitly annotating the parameter with it.

## Options Considered

1. **Remove explicit annotation** — Drop `: Config`, let TypeScript infer from `Hooks` return type
2. **Import Config from plugin** — Switch to `import { Config } from "@opencode-ai/plugin"`
3. **Inline type extraction** — `Parameters<NonNullable<Hooks["config"]>>[0]`

## Final Decision & Rationale

**Chose Option 1**: Remove the explicit type annotation and the import entirely.

Reasoning:
- The plugin entry point doesn't actually need the `Config` import — it's only used as a parameter annotation
- TypeScript correctly infers the parameter type from the `Hooks` return type constraint
- This is the minimal, idiomatic fix — no workarounds, no type gymnastics
- Future dependency bumps with further `Config` changes won't break this pattern

## Key Changes Made

1. **`src/design-lab.ts`**: Removed `import type { Config } from "@opencode-ai/sdk"` and dropped `: Config` annotation on the `config` hook parameter
2. **`package.json`**: Version bumps for all dependencies
3. **`bun.lock`**: Auto-generated lockfile update

## Future Considerations

- The SDK and Plugin `Config` types continuing to diverge could cause issues elsewhere if other modules annotate with the wrong `Config`
- `agents/index.ts` imports `AgentConfig` from `@opencode-ai/sdk` — this is currently stable but worth monitoring
- TypeScript 6.0.3 may introduce new strictness — watch for new errors on future updates
