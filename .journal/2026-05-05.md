# 2026-05-05 — Design Lab: Double-Blind Review System

## Core Decision/Topic

Implement a double-blind review system to eliminate model-name bias in Design Lab evaluations.

## Problem

Review subagents could see model names in design filenames and content, leading to potential bias (e.g., favoring well-known models like GPT-4 over lesser-known ones).

## Solution: Double-Blind Review

1. **Blind setup** — After designs are generated, create anonymized copies in `blinds/designs-blind/` (design-a.md, design-b.md, ...)
2. **Identity stripping** — Remove model identity lines ("Model:", "Generated by", model names in metadata) from blind copies
3. **Mapping file** — Store blind-to-real mapping in `blinds/mapping.json` for the primary agent only
4. **Anonymous reviews** — Review subagents read only blind copies and evaluate purely on technical merit
5. **De-anonymized reporting** — Final reports use real model names from the mapping

## Bug Fixes (from code review)

1. **Blind label overflow** — `String.fromCharCode(97 + i)` failed for >26 models. Fixed with base-26 encoding (design-aa, design-ab, ...).
2. **Example naming inconsistency** — Subagent prompt examples used `model-a` instead of `design-a`. Fixed to prevent subagents from leaking real names.
3. **Missing `$schema`** — Removed in earlier edit. Restored for IDE validation.
