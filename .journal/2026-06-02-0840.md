# 2026-06-02 08:40 - Design Lab Default-Agent Fanout

## Timestamp

2026-06-02 08:40

## Core Decision/Topic

Make Design Lab usable from the normal OpenCode `build` agent while preserving
native, clickable model subagent cards in the TUI.

## Options Considered

- Delegate from the current agent to `design_lab`, then let `design_lab` fan out
  to model subagents.
- Run a plugin tool (`design_lab_run`) that creates a child `design_lab` session
  through the SDK.
- Keep the current/default agent as the coordinator and call native `task`
  directly for each selected `design_lab_model_*` worker.

## Final Decision & Rationale

Use direct native `task` fanout from the current/default agent for bundled-skill
activation. Delegating to `design_lab` worked functionally, but it hid the model
workers one level down as child sessions of a child session. `design_lab_run` was
also functional, but it rendered as a single tool call and could not produce the
native subagent-card UI. Direct fanout makes each configured model worker a
top-level `task` call, matching the desired TUI behavior.

The `design_lab` coordinator remains available for `/design-lab:ask` and direct
agent usage. `design_lab_run` remains a fallback when native `task` fanout is not
available.

## Key Changes Made

- Added bundled `skills/design-lab/SKILL.md` and registered package skills in
  plugin config.
- Added a message transform that nudges matching multi-model prompts to load the
  `design-lab` skill from the current agent.
- Added `design_lab_run` as a fallback bridge tool.
- Changed `design_lab` to `mode: "all"` and enabled native `task` for its own
  coordinator workflows.
- Removed stale `delegate_task` configuration and wording in active source paths.
- Updated default-agent activation so the current agent calls `task` directly for
  selected `design_lab_model_*` subagents instead of delegating to `design_lab`.
- Updated model subagent prompts to accept assignments from either the
  `design_lab` coordinator or the current/default agent.
- Documented the split between default-agent direct fanout and explicit
  `design_lab` coordinator usage.

## Future Considerations

- The direct-fanout path relies on the LLM following the skill instructions for
  run directory setup, manifest writing, and summary synthesis. A future tool
  could provide deterministic setup while still keeping model workers top-level.
- The build still emits the known `tsdown` warning that `noExternal` is
  deprecated in favor of `deps.alwaysBundle`.
- OpenCode must be restarted after rebuilding or installing the plugin so updated
  skill text and hooks are loaded.
