# Journal Entry

## Timestamp

2026-06-02 06:11

## Core Decision/Topic

Replaced the split Design Lab agent topology with one `design_lab` primary agent
that coordinates all multi-model workflows: general asks, plan generation, plan
revision, blind plan review, and same-session code review.

## Options Considered

- Keep separate `designer` and `multi_model` primary agents. This preserved the
  older design/review separation, but created confusing agent switches and made
  it harder to continue a workflow in one session.
- Extend only `/design-lab:ask` while leaving old design/review commands in
  place. This was lower risk but would duplicate orchestration rules across
  commands and agents.
- Use one `design_lab` primary with model-specific `design_lab_model_*`
  subagents. This centralizes orchestration, supports direct agent usage, and
  keeps model workers file-first.

## Final Decision & Rationale

The single `design_lab` primary is now the canonical workflow agent. It does not
set a fixed model, so OpenCode can keep using the active UI/default model for the
coordinator. Configured model subagents still bind to their own models and
variants, which preserves multi-model comparison without surprising primary-model
switches.

The config was simplified to one `models` list plus `default_variant`. Variants
are passed through as arbitrary strings, including provider-specific values such
as `xhigh`, and `variant: null` explicitly disables variants for a model. This
avoids hardcoding provider capability assumptions in the plugin.

For code reviews, subagents are review-only. They read a primary-generated review
packet and write review files, while any source edits remain under the primary
agent and only happen after explicit user approval.
