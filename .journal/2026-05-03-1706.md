# 2026-05-03-1706 — Design Lab: Hot-Reload Config, Variant Support, Error Detection

## Core Decision/Topic

Three major enhancements to the Design Lab plugin in a single working session:

1. **Hot-reloadable config** — Changes to `.opencode/design-lab.json` take effect on next command without restarting OpenCode
2. **Per-model variant (effort) control** — Each model in `design_models`/`review_models` supports an optional `variant` field (`low`/`medium`/`high`/`max`)
3. **Subagent failure detection** — Primary agent now inspects `delegate_task` results for 7 failure patterns and handles them (skip/retry/abort)
4. **Iterative revision workflow** — Primary agent supports revising existing designs, with each subagent only modifying its own file

## Options Considered

### Hot-Reload

- **Option A**: Re-register commands/agents in a hook that fires per-command
  - Rejected: OpenCode's `config` callback fires only once during plugin init
- **Option B**: Move config loading to `config` callback + have command templates read config dynamically
  - **Chosen**: Commands always registered; templates include instructions to read config at runtime

### Effort/Variant

- **Option A**: Global `design_effort` / `review_effort` fields on config
  - Rejected: Inflexible — can't set different variants per model
- **Option B**: Per-model object config with `variant` field, union type in Zod
  - **Chosen**: `ModelConfig = string | { model, variant }` — backwards compatible, strings default to `"max"`

### Error Detection

- **Option A**: Post-execution hook that intercepts delegate_task results
  - Deferred: Adds complexity; prompt-level detection is sufficient for MVP
- **Option B**: Primary agent prompt explicitly instructing failure pattern matching
  - **Chosen**: 7 failure signals defined, 5 action rules (skip/retry/report)
